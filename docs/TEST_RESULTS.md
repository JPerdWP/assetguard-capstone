The test suite exercises Flask routes with actual SQLite databases, not mocked query results. It checks a complete device-to-issue workflow and verifies dashboard values after resolution. It is not a complete security assessment or a load test.

UI evidence: screenshots capture real HTML generated by Flask's test client using the fictional demo database, displayed through a static review server. The Python runtime was unavailable in the browser preview host. The captured views were checked for desktop layout and readable forms, but live browser form submissions were not tested there. Backend form submissions are covered by pytest. Human acceptance testing, Windows execution, narrow-screen behavior, and screen-reader testing remain unverified.

Local timing observations and the separate clean-install smoke result are provided in evidence/verification.json. Timing is a warm local test-client measurement using only the seed dataset; it excludes network latency and is not a production guarantee.

No application defects were observed by the final automated run. Preview setup failed because the managed preview host lacked the Python runtime; it was handled by reviewing rendered page output separately, without changing the application to pretend it was hosted. The added local-tool cases verify that diagnostics preserve saved data and that the Git check detects runtime file paths even after they are removed from the current working tree.
